# Textos do aluno escritos por LLM e custo por aluno — plano de implementação

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** O provisionamento grava no repositório do aluno textos escritos pelo Claude Haiku 5.5 para a vaga dele: uma seção "Seu projeto" no README e o contexto de cada issue de missão. Quando o LLM não responde, entram textos padrão. Um teste separado mede o custo por aluno com 3 vagas fictícias.

**Architecture:** Um pacote novo, `writing`, define a interface `MissionTextWriter`, que nunca lança exceção. Ela tem duas implementações: `ClaudeMissionTextWriter` (SDK oficial, uma chamada com saída estruturada) e `DefaultMissionTextWriter` (sempre vazia, usada quando não há chave). O `StudentRepositoryProvisioner` chama o escritor antes de tocar no GitHub, completa o que faltar com `DefaultStudentTexts`, abre as issues com o contexto e, por último, insere a seção no README da cópia do aluno (`StudentReadme`, função pura) usando duas operações novas do `GitHubApi`.

**Tech Stack:** Java 21, Spring Boot 4.1.2, `com.anthropic:anthropic-java` 3.6.0 (traz o Jackson 2 só para uso interno; o projeto continua usando o Jackson 3, `tools.jackson.databind.json.JsonMapper`), JUnit 5 + AssertJ, `MockRestServiceServer` para o GitHub e `com.sun.net.httpserver.HttpServer` para a API da Anthropic nos testes.

**Spec:** [docs/superpowers/specs/2026-11-06-llm-texts-design.md](../specs/2026-11-06-llm-texts-design.md)

## Global Constraints

- Branch `feat/llm-texts`. Commits em inglês, no imperativo (`Add ...`), terminando com `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Código e identificadores em inglês; todo texto mostrado ao aluno em português, com acentos.
- ADR 0002: o LLM não escolhe, não ordena e não altera missões. A tabela do README e a ordem das issues vêm só do plano.
- ADR 0003: nada do texto da vaga nem dos termos encontrados nela (`matchedTerms`, `evidence`) vai para o LLM, para logs ou para exceções. Os logs do escritor só registram o modelo, os tokens de entrada e saída e a duração; em caso de falha, o tipo da exceção ou o `stop_reason`.
- O provisionamento **nunca** falha por causa do LLM. Erros do GitHub continuam sendo propagados como hoje.
- Modelo `claude-haiku-5-5`, thinking desligado (`ThinkingConfigDisabled`), `OutputConfig.Effort.LOW`, `maxTokens` 4.000.
- Configuração: `vagaviva.llm.api-key: ${ANTHROPIC_API_KEY:}`, `vagaviva.llm.model: claude-haiku-5-5`, `vagaviva.llm.timeout: 30s` (por tentativa), `vagaviva.llm.max-retries: 1`.
- Limites dos textos do LLM: `projectIntro` até **1.500** caracteres e cada `context` até **800**, depois de `strip()`. Texto vazio, mais longo que isso, contendo ```` ``` ```` ou com qualquer linha começando por `#` é descartado e substituído pelo padrão.
- Nenhum teste faz chamada de rede real. A única exceção é `LlmCostMeasurement`, que só roda com `-Dvagaviva.measure-llm-cost=true` **e** `ANTHROPIC_API_KEY` definida.
- As vagas de teste são fictícias, sem nomes de pessoas, e-mails, telefones ou empresas reais.

## Review Focus

1. **O LLM devolve o mesmo id de missão duas vezes, ou um id fora do plano:** vale o primeiro texto, e o id desconhecido é ignorado (teste na Task 4).
2. **O LLM devolve um título Markdown, um bloco de código ou um texto enorme:** só aquela parte cai para o padrão, sem quebrar o layout da issue nem do README (teste na Task 4).
3. **O README do modelo tem `## ` dentro de um bloco de código antes do primeiro título real**, ou usa CRLF: a seção entra antes do primeiro título real e nada mais muda (testes na Task 5).
4. **Competência ou tecnologia sem rótulo no vocabulário:** o prompt e os textos padrão usam o id, como o `MissionIssueText` já faz (teste na Task 3).
5. **O SDK lança uma exceção que não é de rede** (por exemplo, falha ao desserializar) ou a resposta vem sem bloco de texto: o resultado é vazio e o provisionamento segue (teste na Task 4).

### Task 4: `ClaudeMissionTextWriter`

**Files:**

**Interfaces:**
- Consumes: `MissionTextWriter`, `WrittenTexts`, `TokenUsage`, `MissionTextPrompt` (Task 3).
- Produces: `public ClaudeMissionTextWriter(AnthropicClient client, String model, SkillVocabulary vocabulary)`.

Requisição (`com.anthropic.models.messages.MessageCreateParams`):
- `.model(model)`, `.maxTokens(4000L)`, `.system(MissionTextPrompt.SYSTEM)`, `.addUserMessage(MissionTextPrompt.user(plan, vocabulary))`;
- `.thinking(ThinkingConfigDisabled.builder().build())`;
- `.outputConfig(OutputConfig.builder().effort(OutputConfig.Effort.LOW).format(JsonOutputFormat.builder().schema(<schema>).build()).build())`. O schema é montado com `JsonOutputFormat.Schema.builder().putAllAdditionalProperties(...)` e `JsonValue.from(Map)`:

```json
{ "type": "object", "additionalProperties": false, "required": ["projectIntro", "missions"],
  "properties": {
    "projectIntro": { "type": "string" },
    "missions": { "type": "array", "items": {
      "type": "object", "additionalProperties": false, "required": ["id", "context"],
      "properties": { "id": { "type": "string" }, "context": { "type": "string" } } } } } }
```

Resposta:
- Só é aceita se `stopReason()` for `END_TURN`. O primeiro bloco `text` é lido com o `JsonMapper` do Jackson 3 para um record privado `Answer(String projectIntro, List<Item> missions)`.
- Cada texto passa por `strip()` e pelos limites das Global Constraints.
- Ids fora do plano são ignorados; em id repetido, vale o primeiro.
- `usage` vem de `message.usage().inputTokens()` e `outputTokens()`.
- Todo o método fica num `try/catch (RuntimeException)`, e qualquer falha devolve `WrittenTexts.none()`.

Logs (SLF4J): em caso de sucesso, `INFO "LLM texts written: model={}, inputTokens={}, outputTokens={}, millis={}"`. Em caso de falha, `WARN "LLM texts unavailable: {}"`, com `e.getClass().getSimpleName()` ou o `stop_reason`. Nunca registrar o prompt, a resposta nem a mensagem da exceção.

Testes com um `HttpServer` local em `127.0.0.1` porta 0, e o cliente `AnthropicOkHttpClient.builder().apiKey("test-key").baseUrl("http://127.0.0.1:" + port).maxRetries(0).timeout(Duration.ofSeconds(2)).build()`. O servidor guarda o corpo da última requisição e responde um JSON configurado por teste. Resposta-base:

```json
{ "id": "msg_test", "type": "message", "role": "assistant", "model": "claude-haiku-5-5",
  "content": [ { "type": "text", "text": "<JSON do Answer, com escape>" } ],
  "stop_reason": "end_turn", "stop_sequence": null,
  "usage": { "input_tokens": 1200, "output_tokens": 900 } }
```
